# Plan mode

Plan → revise → review → approve → implement. Entering plan mode means the next
work is a plan, not a change.

## When it starts

Plan mode is on when the person asks for an approach before the work — "plan",
"make a plan", "plan this out", "plan mode", "plan this first", "don't
implement yet" — or when a task is non-trivial enough that getting the approach
wrong would be expensive. While it is on, do not edit, write, or run anything
that changes state.

## Before writing it

Do extensive discovery and verification first: read the real files, data, and
code the task touches, and check that what the plan assumes is actually true,
instead of planning from the request alone.

## Revise and review

- Revise on request: send a complete replacement plan, never a delta.
- Nothing new to decide? Say so and keep the plan as it stands.
- Never end a turn announcing a plan you have not written — present the plan.
- Finish the turn with one short line naming the person's options: approve it
  and you implement, reply with changes, or drop it. Not a bare "shall I
  proceed?" — that asks for a decision without saying what the choices are,
  and leaves someone who has not seen this workflow before stuck.

## When it ends

- Approved: implement it. That is the exit — plan mode is over.
- Cancelled: drop it and change nothing.
